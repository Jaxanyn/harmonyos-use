# 前台连续采集能力探针

此目录是独立实验项目，不接入预览插件，也不会自动开始采集。手动点击“开始测试”后才请求系统屏幕共享授权；点击停止、页面退出、应用进入后台或进程退出时尝试停止并释放采集资源；如果释放失败，保留句柄并提示点击“停止”重试。进程退出时无法再通过界面确认或重试。前台事件循环正常运行时，定时器在约 20 秒后停止。权限对话框出现时应用生命周期的具体行为需要真机验证。

仅配置视频；启动前显式请求关闭默认开启的麦克风，关闭失败则不启动采集，并尝试释放资源；回调只统计帧数、时间戳和状态，不读取、保存或传输像素。开始后页面约每 33 毫秒改变小区域标记，统计信息每 500 毫秒刷新；这是变化驱动的近似能力探测，不是端到端延迟测试。请仅在自愿授权且确认屏幕内容适宜共享时运行。

## 验证状态和范围

- 已用本机 HarmonyOS SDK 的 aarch64 交叉编译器编译并链接 C++ 原生库。安装本地类型依赖后，获授权的 DevEco 构建通过 ArkTS 编译和 HAP 打包，生成未签名的 `entry/build/default/outputs/default/entry-default-unsigned.hap`。构建通过不等于真机运行验证。
- 构建存在 EntryAbility 中 `loadContent` 可能抛出异常的警告，尚未处理。未修改 SDK 或签名配置，也未安装或启动设备侧应用。
- 这是前台探针：它不能验证其他应用的画面、画面传输、预览显示延迟、互动控制或帧内容正确性，也不提供生产环境的连续采集路径。系统拒绝授权、息屏、后台切换、重新开始、麦克风关闭和隐私保护区域的行为仍需真机测试。系统终止或发生错误时，页面轮询会在 UI 线程尝试停止和释放采集；未验证定时器及生命周期在各设备上的实际执行顺序。
- 截止目前没有新采集或输出任何屏幕图像。

## 后续运行步骤

1. 使用已配置好的 DevEco Studio 和可用的 HarmonyOS SDK 打开本目录；自行为此独立项目配置有效的开发签名并重新构建签名 HAP，再安装到设备。勿复制或提交其他工程的签名材料；上述 unsigned HAP 不可作为已签名包直接安装。
2. 检查设备已连接并解锁，用户自行安装并打开测试应用。
3. 点击“开始测试”，自行确认或拒绝系统授权；观察状态、帧数和帧率，再点击“停止”。系统有权阻止受保护内容。不要在结果中粘贴画面或敏感信息。
4. 另外验证拒绝授权、返回后台和再次进入的释放行为。结果仅表示这台设备、系统版本和所用配置下的前台能力。
